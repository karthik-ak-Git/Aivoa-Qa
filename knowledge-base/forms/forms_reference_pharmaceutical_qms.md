## 5.2 Example: Deviation Report Form (Form-QA-001)

### Form Fields
| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| Deviation ID | Auto-generated | Yes | Format: DEV-YYYY-NNNN | Unique identifier |
| Report Date | Date | Yes | ≤ Today | Date of report |
| Detection Date | Date | Yes | ≤ Report Date | Date deviation discovered |
| Detected By | Text | Yes | Employee ID lookup | Person discovering |
| Department | Dropdown | Yes | Valid departments | Originating department |
| Product Name | Text | Yes | Product master data | Affected product |
| Batch/Lot Number | Text | Yes | Batch master data | Affected batch(es) |
| Deviation Type | Radio | Yes | Planned / Unplanned | Deviation category |
| Severity | Radio | Yes | Critical / Major / Minor | Risk-based classification |
| Category | Dropdown | Yes | Process / Equipment / Material / Documentation / Environmental / Human Error | Deviation category |
| Description | Textarea | Yes | Min 50 chars | What, when, where, how discovered |
| Immediate Actions | Textarea | Yes | Min 20 chars | Containment, quarantine, notifications |
| Potential Impact | Checklist | Yes | Product Quality / Patient Safety / Data Integrity / Regulatory / Batch Disposition | Impact assessment |
| Assigned Investigator | Dropdown | Yes | Qualified personnel | Investigation owner |
| Target Closure Date | Date | Yes | Based on severity | Auto-calculated |

### Workflow
```
1. Originator completes form → Submit
2. QA triage (24h) → Classification → Assign investigator
3. Investigation → Root cause → CAPA assessment
4. Investigation report (Form-QA-001B) → CAPA initiation (if needed)
5. QA review → Approval → Closure
6. Archival in eQMS
```

## 6. Form Design Principles

### 6.1 Design Standards
| Principle | Application |
|-----------|-------------|
| **Mandatory Fields** | Clearly marked, validation on submit |
| **Dropdowns/Lists** | Controlled vocabularies, master data driven |
| **Auto-calculation** | Dates, IDs, yield calculations |
| **Audit Trail** | All changes logged with user/timestamp |
| **Electronic Signature** | 21 CFR Part 11 compliant where required |
| **Conditional Logic** | Show/hide fields based on selections |
| **Attachment Support** | Photos, PDFs, documents with version control |
| **Mobile Responsive** | Accessible on tablets in production areas |
| **Offline Capability** | Sync when connectivity restored |

### 6.2 Validation Rules Examples
| Field | Rule |
|-------|------|
| Batch Number | Must exist in batch master data |
| Target Closure Date | Auto-calc: Critical=30d, Major=60d, Minor=90d from report date |
| Severity | Required if Deviation Type = Unplanned |
| Sample Available | Required if Category = Product Quality |
| Batch Numbers | Must match product selected |
