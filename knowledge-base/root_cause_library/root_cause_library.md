## 3. Root Cause Analysis Tools Quick Reference

| Tool | Best For | Steps | Output |
|------|----------|-------|--------|
| **5 Whys** | Simple, linear cause chains | 1. State problem<br>2. Ask "Why?"<br>3. Repeat 5x<br>4. Verify root cause | Single root cause statement |
| **Fishbone (Ishikawa)** | Multiple potential causes | 1. Define effect<br>2. Draw spine<br>3. Add 6M branches<br>4. Brainstorm causes<br>5. Prioritize | Categorized cause map |
| **Fault Tree Analysis** | Complex system failures | 1. Define top event<br>2. Identify intermediate events<br>3. Add logic gates (AND/OR)<br>4. Identify basic events<br>4. Quantify if data available | Logic diagram with probabilities |
| **FMEA** | Proactive risk assessment | 1. List process steps<br>2. Identify failure modes<br>3. Rate S, O, D (1-10)<br>4. Calculate RPN<br>5. Prioritize actions | Prioritized risk register |
| **Change Analysis** | Post-change deviations | 1. Define problem<br>2. Identify what changed<br>3. Compare changed vs unchanged<br>3. Analyze differences | Specific change root cause |
| **Pareto Analysis** | Prioritizing multiple causes | 1. Collect data<br>2. Categorize<br>3. Count frequency<br>4. Sort descending<br>5. Calculate cumulative % | 80/20 prioritization |
| **Barrier Analysis** | Safety/quality barrier failures | 1. Identify hazards<br>2. Identify barriers<br>3. Assess barrier effectiveness<br>4. Identify failed/missing barriers | Missing/ineffective barriers |

## 4. Root Cause Verification Checklist

| Verification Step | Description | Complete? |
|-------------------|-------------|-----------|
| **Specificity** | Root cause is specific, not generic (e.g., not "human error") | ☐ |
| **Evidence-Based** | Supported by data, documents, testing, observations | ☐ |
| **Causal Link** | Clear causal chain from root cause to effect | ☐ |
| **Systemic** | Addresses system gap, not just symptom | ☐ |
| **Actionable** | Leads to specific corrective/preventive actions | ☐ |
| **Verifiable** | Can be confirmed through testing, audit, observation | ☐ |
| **No Blame** | Focuses on system/process, not individual blame | ☐ |
| **Preventive** | Leads to preventive actions, not just corrective | ☐ |
| **Scope** | Addresses all affected products/batches/processes | ☐ |
| **Documented** | Fully documented with evidence trail | ☐ |
